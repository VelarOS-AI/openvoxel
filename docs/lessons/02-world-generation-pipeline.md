# 第二课：让每个 Chunk 独立知道整个世界

旧项目生成树或洞穴时会先准备周围 Chunk，再让笔刷直接修改邻块。这种做法容易写出第一版，但会让生成顺序、并行调度、缓存和网络请求彼此纠缠。

OpenVoxel 换了一个问题：不是“我怎样修改邻居”，而是“哪些世界坐标特征有资格影响我”。

阅读顺序：

1. `packages/content/identities/data/identities.yml` 定义全部内建身份；`packages/content/blocks/data/catalog.yml` 与 `data/blocks/` 定义方块类型和有限状态。生成工具把它们编译为 `generated/block-catalog.json`，`@openvoxel/blocks` 再构造生成、模拟和渲染共享的受检查注册表。
2. `packages/world/generation/src/survival/terrain.vel` 把种子变成气候、高度与密度，观察二维宏观地貌和三维局部扰动如何叠加。
3. `ColumnPlanner` 展示同一水平 Chunk 的 `ColumnCache` 如何跨垂直层复用，再由岩体、地表和植物三个阶段共同读取。
4. `survival/caves.vel` 从洞穴锚点开始阅读，注意每个随机流都由功能和世界坐标命名；`feature-plan.vel` 负责世界坐标特征的裁剪与分桶。
5. 比较树木与矿脉：形状不同，但“扩展查找锚点，只写目标 Chunk”的边界相同。
6. 回到 `generator.vel`，完整顺序只有基础岩体、洞穴、流体、矿物、地表、植被六个调用。
7. 最后查看固定种子、稀有矿物和跨边界树冠测试，理解算法描述如何变成可执行契约。

洞穴仍然遵守“重放特征，只写目标 Chunk”，但不会为每个相邻 Chunk 重新推演整条路径。一个世界内的 `CavePlanner` 按所有者坐标缓存连续球体序列和整体包围盒；目标 Chunk 先拒绝不相交的计划，再检查剩余球体。缓存有固定上限且随 `WorldGenerator` 生命周期存在，淘汰只损失速度，不改变任何生成结果。

地形柱也是同一原则。同一个 `(chunkX, chunkZ)` 无论生成多少个 Y 层，温湿度、生物群系和地表高度都不变，因此 `ColumnPlanner` 用不含 Y 的键保存 192 个最近使用的水平结果，容纳当前视区、释放迟滞与一次相邻窗口过渡。它不缓存最终 Chunk，也不接受其他区块写入；满了只淘汰最久未使用项，下次仍可从种子得到逐位相同的结果。

最重要的可迁移结论是：确定性不是“每次使用同一个 seed”这么简单。真正的确定性要求每个子系统有独立随机命名空间、每个跨区结构有稳定所有者、每个阶段有固定覆盖规则，并且持久化清楚记录生成器版本。

## 从方块目录到可见的生态群落

`survival/ecology-patterns.vel` 用连续世界坐标场决定覆盖度和优势种，`ground-plants.vel`
负责花草、作物、幼树与落叶的地表准入，`natural-ecology.vel` 负责枯木、藤蔓与浅水生态。
逐株随机流负责混生、成熟度和形态，不能让每个 Chunk 单独挑一种植物。
水生植物只在 2–16 格深的合适水底生成，海带向水面延伸并保留上方水层；
藤蔓从真实树形的外露支撑处开始，避免候选全部落在叶片里。

验收既检查生态支撑约束，也检查小范围内的最终方块密度、花丛相邻关系和跨区连续性。
在生成包运行 `velar run tools/ecology-survey.vel` 可对照候选写入与最终 Chunk：
目录中有名字、宽范围扫描找到一次，都不足以证明玩家能看见该生态。
群落尺度和采样参数属于生成器定义，参与世界清单哈希；查看改变后的生成规则应创建新世界。

## 地貌、岩性和出生海岸

`survival/terrain.vel` 在大陆骨架之上叠加独立的海岸丘陵与内陆山脊。体素密度使用
真正的三线性插值，避免在粗网格节点重复缓动而形成规则平台。Halo 的坡度也读取
真实邻列高度，同一世界坐标在相邻 Chunk 必须得到相同的地表和植物支撑判断。

`surface-materials.vel` 按连续岩性、沉积、露头和岩脉场选择基底：陡坡露出母岩，
湿润河岸沉积黏土，沙岸与砾岸按沉积条件过渡，大理石以自然岩脉露头穿过草坡。
这些场使用独立种子和世界坐标；表层与近地表岩体读取同一份岩性。

`coastal-spawn.vel` 用近、远两级水域探针为海岸加权，最后仍检查真实水位和玩家
脚部、头部碰撞。粗高度仅在一次搜索内缓存；找不到合适海岸时仍选择安全陆地。

森林的露天地表保留草皮，沉积场影响湿地、海岸和底土；落叶由生态层按支撑条件铺设。
这吸收了生存战争 `GenerateGrassAndPlants` 的地表覆盖顺序。山地、丘陵与平原由
大尺度山脊带分开控制，河流侵蚀只降低原始高度，海底深度保持大陆场自己的结果。

树形参考 `PlantsManager.CreateTreeBrush` 的枝干支撑和分层叶密度思想：橡树以
枝端组合团簇，桦树与白杨保持细长冠层，云杉以错层细枝承托连续收尖的锥冠，金合欢
以分枝承托有厚度的伞冠。六种树各有四种有界变体；边缘缺口使用局部坐标和变体
确定，冠层写入合并后每格只出现一次，枝干优先。包络由合法高度与全部变体穷举，
连通性检查确保叶片能通过面相邻路径连接到树根。桦树、白杨和高云杉分别使用自己的
温湿度色表，颜色更新不要求重建区块网格。

特征避让先比较包围盒，再以世界坐标集合做精确交集，复杂度为两个特征的写入数之和。
`survivalAlgorithmRevision` 与参数、调色板、气候版本一同参与世界指纹；代码生成语义
改变时递增该值。旧指纹不会继续生成新区块，验证本轮效果应创建新世界。

资源模型离线转换为带局部坐标、法线、逐面 UV 的中立三角形数据，位于渲染包的
`data/models/vegetation/`。仙人掌、南瓜、海星和海胆使用实际模型，方块运行时 ID
与模型身份保持分离。`tools/import-natural-models.py` 负责素材导入，正常构建读取
中立数据并校验边界。大理石采用原素材的默认纹理槽 7，彩绘槽与默认槽分别处理。

多地点验收：先运行 `npm run build:workspaces -- @openvoxel/world-generation @openvoxel/game`，再运行
`npm run test:terrain -- after --discover --sites=forest,coast`。工具通过真实生成器、区块网格
与游戏渲染适配器截取俯视和近景图，固定种子与坐标保存在 `generated/terrain-tour/`，
复拍沿用原坐标；算法改变后用 `--discover` 更新采样点。默认只检查出生点、森林和
海岸，`--all` 显式检查完整样本，`--radius=2` 至 `--radius=5` 控制截图生成范围。
页面仅在测试期间启动，结束时关闭浏览器和服务器。
