# ADR 0004：生存战争式世界生成

状态：已接受

## 来源与边界

生成器参考两个已放弃项目中的执行顺序、参数和《生存战争》式地形思路，保留海平面、气候、海岸、山地、河流、三维岩体扰动、洞穴笔刷、矿脉和气候植被这些核心行为。旧项目的柱状 Chunk、共享邻居缓存和分阶段修改邻块不进入新架构。

生成算法属于 `@openvoxel/domain`，只使用 VelarScript 的确定性随机、Simplex 噪声和定长缓冲区；方块身份与属性来自独立的 `@openvoxel/blocks`。算法、方块目录和世界参数都不会写入 VelarScript 标准库。

## 生成顺序

`openvoxel:survival-v1` 对目标 16³ Chunk 执行固定顺序：

1. 从世界种子派生互不干扰的气候、海岸、山地、河流、岩层和植被噪声场。
2. 为目标的 256 根 `(x,z)` 地形柱计算温度、湿度、海岸距离、山地因子、生物群系和地表高度。
3. 以高度场加三维扰动计算每个体素的密度；负密度为空气或海水，正密度按深度、沙漠和岩层噪声选择岩石。
4. 由世界坐标特征锚点刻蚀洞穴，再生成地下水与岩浆口袋。
5. 用选择性矿脉只替换对应母岩，生成煤、铜、铁、硝石、硫磺、钻石和锗。
6. 在洞穴与矿物之后铺设有限厚度的沙、黏土、砾石、泥土和草层，洞口不会被重新封死。
7. 最后按温湿度、海拔和森林密度生成积雪、草、花、枯灌木、仙人掌与五类树木。

海水直接由世界坐标和海平面决定，不再运行一次依赖邻块的“向下传播流体”修补阶段。

## 跨 Chunk 所有权

洞穴、矿脉、流体口袋和树木都由固定大小的世界坐标网格拥有。目标 Chunk 会在有限扩展范围内重放可能影响自己的锚点，但只写入自己的 4096 个方块。

因此：

- 生成 A 后生成 B，与先生成 B 后生成 A 完全一致。
- 树冠、洞穴和矿脉可以跨越 X、Y、Z 边界，不要求邻居已经存在。
- 浏览器 Worker 和 Node 服务只要输入同一清单与坐标，就得到相同校验和。
- 并行化不需要世界级生成锁，也不会出现半生成邻块。

## 性能策略

- 一个世界只创建一个可复用 `WorldGenerator`；`WorldRuntime` 按世界缓存它，批量和后续 Chunk 共享同一组只读噪声场。
- 单个地形柱样本里的海岸距离和山地因子只计算一次；同一水平 Chunk 的 256 根地形柱及精确表面高度由 `WorldGenerator` 的 64 项 LRU 缓存跨 Y 层复用，基础岩体、地表和地面植被共享同一结果。
- 地形柱缓存和洞穴计划缓存都只是确定性计算的加速层：键只含拥有结果的世界坐标，淘汰后从种子重建，绝不作为世界状态或生成权威。
- 每类特征只有一个随机根，再按锚点标签 `fork`；随机消费顺序和调度顺序互不耦合。
- 洞穴所有者的球体序列和整体包围盒由 `WorldGenerator` 的有界计划缓存复用；缓存不是生成权威，淘汰后可由种子与所有者坐标原样重建。
- 洞穴和矿脉只检查能触达目标 Chunk 的有限锚点；洞穴先拒绝不相交的整条计划和单个球体，再直接写入目标缓冲区。
- `UInt16Buffer` 原地写入 4096 个方块；完整缓冲区只在内存和响应阶段存在，不复制进数据库。
- 世界高度外的 Chunk 在创建地形柱缓存和运行任何特征阶段之前直接返回全空气。

`npm run benchmark:worldgen` 使用固定种子、坐标集和聚合校验和建立 Node 基线；`npm run benchmark:columns` 比较垂直层重复计算与水平地形柱缓存；`npm run benchmark:caves` 比较逐 Chunk 重放与洞穴计划复用。两个专项基准都要求优化前后校验和相同。未来实验 8、16、24、32 等 Chunk 边长时，必须同时比较吞吐、响应体、网格重建成本和客户端访问局部性，不能只比较单次生成耗时。

## 版本规则

固定种子黄金校验和是生成器契约。若修复会改变既有世界，必须新增生成器名，例如 `openvoxel:survival-v2`，并让旧名字继续指向旧算法；只有不改变结果的性能优化可以保留当前名字。

生成数据本身不持久化。只要世界清单继续指向原生成器版本，任意未修改方块都能重新得到相同值；SQLite 和未来的浏览器存储只保存相对这个结果的稀疏覆盖。
