# ADR 0008：世界存档与方块目录兼容性

状态：已接受

## 裁决

世界里的方块以 UInt16 ID 存储，因此每个 `WorldManifest` 必须同时持久化 `blockCatalogVersion` 与 `blockIdMapHash`。目录版本表达发布者声明的兼容系列；ID 映射哈希只由按 ID 排序的 `{id,key}` 列表计算，渲染、标签或模拟属性变化不会误判为数字解释变化。覆盖完整 YAML 的 `contentHash` 只用于目录传输和客户端资源缓存，不写入世界清单。

创建世界时写入服务当前身份；读取清单、生成 Chunk、恢复覆盖或接受外部方块 ID 前都走同一个共享注册表校验。世界身份不匹配、未知 ID 或 `retiredIds` 中的墓碑 ID 都必须显式失败，禁止把旧数字静默解释为另一个方块。

## SQLite 迁移

应用数据库 schema 当前为 2，由 `PRAGMA user_version` 管理。启动顺序固定为：

1. 拒绝高于当前版本的数据库。
2. 建立基础表；为旧 `worlds` 表增加非空目录身份列。
3. 将版本 0/1 的已有世界回填为 `openvoxel:base-v1` 和当前已发布 ID 映射哈希。
4. 扫描全部世界身份与去重后的覆盖 ID；任一不兼容即停止启动。
5. 完成校验后才创建运行时并监听网络。

这次回填成立的前提是 schema 0/1 只由尚未发布第二套 ID 映射的 OpenVoxel 版本产生。未来一旦发布新的映射，迁移必须给出明确转换表或拒绝，不能再使用“当前值”回填。

## 客户端握手与缓存

`GET /api/worlds/:worldId/bootstrap` 是读取 Chunk 前的启动契约，返回协议、世界格式、生成器、目录版本、ID 映射哈希、目录内容哈希和空间/批量限额。客户端先核对该响应，再复用或获取 `/api/blocks`。

`GET /api/blocks` 使用完整目录 `contentHash` 作为强 ETag，支持 `If-None-Match` 与 304。目录对象在服务进程中只构造一次；标签集合也在注册表初始化时预建，热路径不重复分配集合。

## 失败与可观测性

服务启动日志记录目录版本、ID 映射短哈希和内容短哈希。世界目录冲突使用稳定的 `WorldBlockCatalogMismatchError`，包含实际值与期望值；配置加载错误必须给出解析后的绝对路径。自动测试覆盖固定哈希、旧库回填、未来 schema 拒绝、目录冲突、未知/退役 ID、HTTP/WS 输入、缓存命中和数据库重启恢复。
