# ADR 0012：世界模型与世界生成边界

状态：已接受

## 裁决

不使用含义宽泛的通用 `domain` 包。世界相关规则按事实模型、生成算法和应用用例拆成三个明确所有者：

- `@openvoxel/world` 拥有坐标、Chunk、调色板和 `WorldManifest`。它只验证数据结构与世界格式不变量。
- `@openvoxel/world-generation` 拥有 `WorldGenerator`、生成器身份解析、地形采样和各生成阶段。它只根据世界清单和坐标计算基础世界。
- `@openvoxel/world-runtime` 拥有 `CreateWorld`、默认值装配、批量查询限制、每世界缓存、差异叠加和存储端口。

`@openvoxel/blocks` 独立拥有方块定义、状态身份和每世界方块注册表。`world` 可以验证 UInt32 状态 ID 并在清单中保存注册表快照；`world-generation` 可以查询内建生成语义；两者都不能重新定义方块。

## 世界模型

`world` 回答“世界中的数据是什么”：

- 整数世界坐标如何映射到 Chunk 坐标和局部坐标。
- Chunk 如何以 UInt32 状态 ID 调色板和 UInt16 局部索引保存 16³ 体素。
- 世界清单必须包含哪些稳定事实，以及这些字段满足什么范围。

空 Chunk 的填充值必须由调用方提供。世界模型不读取全局空气身份，也不选择默认生成器或基础方块注册表。`paletteIndex` 只是从调色板重建的进程内查询索引，不进入存储和协议投影。

## 世界生成

`world-generation` 回答“给定清单和坐标时，基础世界是什么”。生成器不读取存储，不叠加玩家修改，也不执行流体传播、重力、光照、掉落或其他 Tick 系统。

生存生成器按地形、洞穴、地下流体、矿物、地表和植被阶段组织。跨 Chunk 特征使用世界坐标拥有者并裁剪到目标 Chunk；列缓存和洞穴计划缓存只加速可重建计算，不成为世界状态。

## 应用运行时

`world-runtime` 回答“如何使用世界”：创建清单、选择默认生成器与基础注册表、按世界缓存生成器和方块注册表、查询 Chunk、叠加稀疏覆盖、提交方块修改。HTTP 批量请求公布的上限来自运行时策略，不属于世界格式。

存储、HTTP、WebSocket、SQLite 和浏览器 Worker 继续由端口与适配器拥有，不能进入 `world` 或 `world-generation`。
